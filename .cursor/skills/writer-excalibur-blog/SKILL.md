# Excalibur BLOG — Writer

## Вход

- `memory/brief/site-brief.md`, `conversion-map.md`

## Задача

1. **Только режим B** — инструкция/гайд/чеклист/comparison. Режим A запрещён.
2. Outline H2 = подзадачи с **действием** (не «вообще про тему»).
3. **ПРОСТОЙ ЧЕЛОВЕЧЕСКИЙ ЯЗЫК (ГЛАВНОЕ ПРАВИЛО):** Пиши максимально понятно и доступно для простого человека (предпринимателя, новичка, не-программиста). Исключай сложный технический снобизм. Любой используемый термин (API, RAG, Self-hosted, Docker) **обязан** иметь моментальную расшифровку и объяснение «на пальцах» (на простых аналогиях).
4. **ОФОРМЛЕНИЕ ТЕКСТА (БЕЗ ДЛИННЫХ ТИРЕ И ЁЛОЧЕК):** Запрещено использовать длинные тире («—») и кавычки-ёлочки (««», «»»). Всегда используй среднее тире («–») или обычный дефис («-»), а вместо кавычек-ёлочек — стандартные прямые двойные кавычки («"`»).
5. Hook 350–500 символов: боль → ответ → **что сделает читатель**.
6.  Минимум **5** нумерованных шагов `<ol>` + workflow (`→`) или таблица.
7. Каждый H2: рекомендация с **точными** маркерами из `memory/brief/editorial-policy.json` → `recommendation_markers_ru` (utility + human-voice gates считают подстроки). Используй в тексте: **«Сделайте» / «Не делайте»**, **«чеклист»** (слитно, не «чек-лист»), также «шаг », «проверьте», «используйте», «избегайте», «ориентир». UI-ярлыки «Делать/Не делать» **не** засчитываются.
8. Body 8 500–9 500 знаков, FAQ 5–7 пар — **ответы-действия**, **один** блок `<h2>Частые вопросы</h2>` (без второго FAQ).
9. `article.meta.json`: `article_mode: B`, `char_count`, `meta_ab` с A/B/AEO оптимизацией:
   - `title_seo`: 35–75 симв, точный `primary_query` в начале + триггер.
   - `title_ctr`: 40–100 симв, кликабельный крючок, обязательно эмодзи (например 💻, 🚀) или знаки ?, !
   - `title_aeo`: 35–90 симв, сформулирован как вопрос ИИ-поисковику (начинается с "Как", "Что", "Почему" или содержит "?").
   - `description_seo`: 100–180 симв.
10. Подзаголовки H2 должны начинаться с **глаголов действия** (создайте, настройте, проверьте) или содержать **маркеры действия** (как, чеклист, сравнение, выбор, пошагово). Минимум 3 H2 должны быть активными.
11. **RSS И ДЗЕН-СОВМЕСТИМОСТЬ (КРИТИЧЕСКИ):** Тело статьи `article.html` должно быть чистым, семантическим HTML без JS-кнопок, инлайновых стилей `style="..."` или кастомных тегов. Выжимки TL;DR оборачивай строго в тег `<blockquote>` (он нативно рендерится Дзеном как цитата). Блоки кода/JSON в `article.html` — **не** `<pre><code>` (HTML linter whitelist); оформляй через `<blockquote>` / таблицу / список.
12. **СТРУКТУРНЫЕ ЭЛЕМЕНТЫ (TL;DR, EEAT — без оглавления):** 
    - Сразу после Lead-абзаца вставляй блок `<blockquote>` с выжимкой ключевых инсайтов (**AEO TL;DR Box**).
    - **ЗАПРЕЩЕНО:** интерактивное оглавление — `<ol>` или `<ul>` с `<a href="#...">` на заголовки H2/H3 сразу после TL;DR. После blockquote TL;DR идёт контекстный `<p>`, затем первый `<h2>`.
    - Атрибут `id` у `<h2>` — только если нужен для внешней перелинковки; не создавай оглавление в теле статьи.
    - В конце статьи (перед FAQ) вставляй блок верификации (**Fact Check Box**) через `<blockquote>` от редакции Авто-Сейлс. **Не** упоминай Wordstat и Метрику в тексте статьи.
13. **CTA `href`:** в publishable `article.html` только живые URL (каталог/Telegram из conversion-map). **Запрещено** оставлять литерал `[REDACTED]` в `href` — link-verify считает это битой относительной ссылкой. Redact только в ledger/commit-артефактах при необходимости secret-scan.
14. В lead обязательно маркеры боли из `pain_markers_ru` (`боль`/`проблем`/`ошиб`/…) — иначе human-voice gate BLOCK.

## Git commit в Cloud (secret redact)

Если `pre-commit.cursor` падает только с `[REDACTED]: invalid variable name`:

1. `git diff --cached` — только нужные артефакты, без handoff/fragments и raw secrets.
2. Допустим `git commit --no-verify` для article/schema файлов, затем push.

На следующих Cloud boot install-скрипт патчит hook (`scripts/excalibur_blog_patch_precommit_secret_scan.sh`), пропуская non-identifier secret names (URL-shaped injects). Если патч уже применён — обычный `git commit` должен проходить.
